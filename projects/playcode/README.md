# PlayCode AI

> Research status: **Architecture-level** · Lifecycle: **active** · Last reviewed: **2026-08-12**

PlayCode has evolved from an online code playground into a hosted AI website and application builder. The current ordinary-user loop combines chat generation a selectable visual surface direct source access publication and—in the application path—database-backed runtime state with coordinated recovery.

## The product now owns more than code preview

The official website-builder contract lets a user describe a site answer clarifying questions inspect the live result select elements for visual edits continue through chat and publish. Real React Vue or HTML source remains visible and exportable. The application-builder path adds backend database authentication files and jobs to the same managed project.

## Recovery reveals the authority boundary

PlayCode documents three related durability layers: full-project snapshots covering code files and database; Git history on separate infrastructure; and encrypted off-site backup. Rewind restores the managed runtime state together rather than only checking out a front-end file. This makes `managed-app-project` the primary architecture while source access and a live visual projection remain meaningful secondary paths.

## Public source is historical

The two public repositories identify the current product but only expose a README and the deprecated desktop client. They do not reveal the current agent protocol storage schema or source-mapping implementation. The dossier therefore stays architecture-level and treats first-party operational claims as the evidence ceiling.
