# gstack-game

> Research status: **Source-level** · Lifecycle: **active** · Last reviewed: **2026-08-12**

gstack-game defines Design as the disciplined judgment layer of game production. It does not claim to build features or assets; its skills protect early ideas, structure a GDD, test core loops and economies, plan a prototype slice, translate decisions into implementation criteria, diagnose game feel and playability, then review QA and release readiness.

## Structured project records feed the next review

Outputs persist under a project store so downstream skills can read the same concept, GDD, scores, handoff and unresolved risks across sessions. Review modes use explicit dimensions and completion states such as done-with-concerns rather than allowing a persuasive conversation to erase missing evidence.

The project borrows gstack's engineering pattern and cites Claude Code Game Studios and other game-design sources, but says its domain judgments and workflows are rewritten. The independently maintained game-specific pipeline is therefore counted separately while its upstream lineage remains explicit.
