# SWE Atlas

> Research status: **Source-level** · Lifecycle: **active** · Last reviewed: **2026-08-12**

SWE Atlas treats wireframes and working HTML prototypes as the exploration layer of software engineering, not decoration added after implementation. Agents move from problem framing to visual alternatives, record decisions, and only then convert the agreed experience into production code.

## A living HTML specification bridges decision and implementation

Wireframe and prototype commands create artifacts that stakeholders can inspect before code hardens. The chosen HTML specification remains a living source of interaction, layout and state intent while decision logs explain why alternatives were rejected. Production code is downstream and must remain traceable to that reviewed intent.

This makes Atlas a product-delivery methodology with concrete visual artifacts. Its broad software-engineering skills are supporting context; the decisive Design mechanism is the explicit explore-review-specify-build transition.
