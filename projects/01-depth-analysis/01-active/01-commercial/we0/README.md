# We0.ai

We0 has two answers to "what is design" that must not be collapsed, because the product is mid-transition. In the current managed product, design is the **site project** — business goals and brand material in, then planning proposals, visual iterations, editable pages, CMS data, domain config and release state all held and published from one managed project in which pages, data and shipping outrank any single code snapshot ([current product](https://we0.ai/)). Design is a continuously operated web property, not a deliverable.

The public `we0-dev/we0` repository exposes the earlier, arguably more revealing answer: design as a **file-oriented workbench** driven by a chat stream. A client parses assistant messages carrying Bolt-style artifact and action tags into a file store, and a WebContainer-backed IDE runs that filesystem so the preview iframe is a live projection of the running source, not a separate canvas document ([pinned chat handler](https://github.com/we0-dev/we0/blob/3258d6d8348e56e8580bcbec8e42a3894d6113d6/apps/we-dev-next/src/app/api/chat/handlers/chatHandler.ts), [WebContainer filesystem adapter](https://github.com/we0-dev/we0/blob/3258d6d8348e56e8580bcbec8e42a3894d6113d6/apps/we-dev-client/src/components/WeIde/services/webcontainer/filesystem.ts)). Here the implementation shows why the chat is not itself the artifact: messages can be persisted and replayed, while the runtime filesystem and preview carry their own lifecycle, and ZIP export and a deploy route create separate delivery copies ([deployment route](https://github.com/we0-dev/we0/blob/3258d6d8348e56e8580bcbec8e42a3894d6113d6/apps/we-dev-next/src/app/api/deploy/route.ts)).

What makes the transition legible is that the current service narrates specialized planning, design, technical and SEO/GEO roles — functional specialization without a public contract for an independently recoverable transaction across all of them. The repository's HTML-to-design and Figma entry points point backward toward the file-and-execution grammar; the hosted product points forward to a managed site with CMS and growth. We0's own evidence is a pivot: the artifact of record moved from a reproducible running filesystem to a managed, published property, and the two layers are best read as one lineage operating at different moments.
