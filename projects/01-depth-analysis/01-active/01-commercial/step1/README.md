# Step1

Step1 defines design as *editable source that starts from someone else's pixels.* The whole product is organized around acquiring a visual starting point — a prompt, a cloned page, a borrowed component, or an imported site — and turning it into a project you can keep changing in natural language. [Get started](https://docs.step1.dev/en/get-started). That starting point is a deliberate strip-down: cloning imports visual UI only, and the docs say application logic, data behavior and existing interactions do not arrive with it. "Pixel perfect" is a claim about reconstructed appearance, not semantic equivalence to the source site. [Clone boundary](https://docs.step1.dev/en/clone)

The implementation is one loop: prompt or clone becomes a Step1 project source; natural-language edits mutate that source; the product observes compile and runtime errors and attempts repairs; the rendered preview feeds back into more edits. [Basics / debugging](https://docs.step1.dev/en/basics). The distinctive persistence mechanism is the message-linked restore point — the conversation becomes a mutation history a user can rewind to, with a top-level restore control, rather than a transcript that only records what was said. So the design is not the screenshot and not the chat: it is the hosted editable project that owns the visual result and the publication path.

Two provenance paths get special treatment. Magic Fusion points at an element on an external page and describes how to fuse that direction into the current project, adapting it to the retained site rather than saving a static reference. Import brings an existing site's visuals into the same authority. Both converge on the same editor, so Step1 is counted as one project rather than separate clone/generator tools. [Step1 documentation](https://docs.step1.dev/en) · [Current product](https://step1.dev/). The closed implementation leaves the DOM-to-source capture method, internal code representation and exact repair policy unverified — so the product's confidence language (pixel-perfect, "just works") is treated as claim, not implementation evidence. Step1's design answer: a captured appearance you can keep editing until it stops being someone else's and starts being yours.
