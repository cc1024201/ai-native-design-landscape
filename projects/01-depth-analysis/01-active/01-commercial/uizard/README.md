# Uizard

Uizard answers the question "what is design" with a native prototype graph, not a codebase. Prompts, screenshots, hand-drawn wireframes, URLs, templates and blank-canvas editing all enter through different recognition or generation paths, and every path converges on the same outcome: editable Uizard screens and native objects inside one hosted project. There is no application source because application source is not Uizard's authority — the prototype graph is. That single decision explains almost everything else about the product, from its coherency before handoff to its deliberate asymmetry after it.

The decisive mechanism is **native object identity**. An AI-selection mutation carries `$prototypeId` plus `$selectedNodeIds`, and completion returns a mutation-shaped command (`add / modify / delete`) for that project rather than pixels or DOM-to-source diffs ([Autodesigner](https://support.uizard.io/en/articles/7728147-guide-to-autodesigner)). A generated screen, a scanned screenshot and a manually drawn screen become peers in one graph; a screenshot or wireframe is a lossy reconstruction into that graph, with no public contract binding each node back to a pixel region or OCR span. AI output is not a separate artifact class — once accepted, its objects enter the exact editing vocabulary humans use.

Two clocks keep generation honest. The prototype graph records what was actually accepted, modified or deleted; a separate project-scoped AI chat ledger preserves prompts, responses and reusable candidate components that can be reinserted later with "Use in design". Theme and Brand Kit operations are materialized `objectsPatch` projections, not live design tokens: apply a theme and you can undo once, but an older theme cannot otherwise be restored. Persistence matters too — autosave is not version history, and no public mechanism establishes a named immutable project revision or whole-project restore.

Handoff is deliberately plural and lossy. Static JPG/PNG/PDF/SVG exports flatten the graph, while the developer exits are component-scoped CSS or React forks that carry no reverse identity back to the project ([export guide](https://support.uizard.io/en/articles/6380330-exporting-projects)). An entire project cannot be exported as runnable HTML or JavaScript, a public link is only a clickable prototype projection, not a functional site, and an application screenshot re-imported later is a fresh reconstruction, not a roundtrip. The ordinary user's central risk is mistaking a hosted, autosaved, clickable artifact for recoverable version history or production implementation.

## Recognition of where the ceiling is

All of this rests on observable public evidence — the product site, help center, and a hash-pinned anonymous client bundle that exposes GraphQL operations like `CreateDesignFromText`, `TextTo*Complete` and `applyBrandKitToPrototype`, configured against separate GraphQL, subscription and multiplayer sockets. What remains closed is the server: native object serialization, the generation/OCR models, conflict resolution across simultaneous human/AI/multiplayer mutations, and the fate of deleted projects (the production bundle carries an `archivePrototype` path the help center does not describe). Uizard is precisely coherent on its own graph and has no public reverse identity outside it.
