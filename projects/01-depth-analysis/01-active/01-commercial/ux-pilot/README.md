# UX Pilot

UX Pilot treats design as a *journey before it is a screen.* Its definition of the design act is upstream of layout: a prompt becomes a connected flow of screens, interactions and decision points, and high-fidelity screens are generated on top of that flow rather than inferred one frame at a time. [UX flow generator](https://uxpilot.ai/ux-flow-generator) · [Product](https://uxpilot.ai/). Follow-up prompts can add screens, reroute navigation or restructure the journey in place, so the design authority carries both each layout and its role in an end-to-end experience. Calling it a screen generator misses the bound-together sequence that owns it.

The implementation is a chained generation pipeline: a PRD, sketch, PDF, screenshot or prompt becomes a structured editable flow, which becomes editable wireframes, which branch into four candidate visual directions, compared side by side so the user selects one, which then continues outward into Figma or into code delivered to GitHub. [UX flow generator and continuation contract](https://uxpilot.ai/ux-flow-generator). Wireframes move from low to high fidelity inside the same workflow, and the entering artifacts are described as becoming structured, editable layouts — not merely image references.

Two external continuations define where design ends. The Figma connection is a two-way retrieval workflow, letting the product import components and synchronize a design system that then constrains generation — grounding output in reusable component identity rather than a style screenshot. GitHub delivery is a separate projection that pushes ready-to-use code to a repository. [Privacy / company](https://uxpilot.ai/privacy). The public surface does not document conflict resolution or perfect preservation for every Figma property, nor does evidence show later GitHub edits flow back into the hosted UX graph — so Figma and GitHub are best treated as separate downstream authorities, not mirrors of the hosted flow. The product's native design truth is the structured, connected flow it lets you keep restructuring; screens, Figma documents and repositories are its projections.
