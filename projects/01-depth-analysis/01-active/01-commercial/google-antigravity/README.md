# Google Antigravity

Antigravity declines to give design a single home, and that refusal is the interesting move. Design is not a canvas, a generated screen, or a prompt reply — it is whatever a conversation successfully mutates across five surfaces (2.0, IDE, CLI, Python SDK, Gemini API) that Google claims share one agent harness. The product's answer to "what is design" is effectively *"the reviewable repository result"*: the working authority is always a real folder, a per-conversation Git worktree, or a managed remote environment, never the plan, diff, screenshot, recording or walkthrough that makes the work legible. [Antigravity overview](https://www.antigravity.google/docs/overview)

The implementation is built around separating evidence from authority. Plans, diffs, diagrams, screenshots, recordings and walkthroughs are control objects that can exist before a write, describe a write that never happened, or go stale after files change — so an accepted plan or a green task proves nothing about the current tree. [Artifacts](https://www.antigravity.google/docs/artifacts) · [Artifact review](https://www.antigravity.google/docs/artifact-review). The mutation authority is intentionally plural: Local Mode writes real folders directly, New Worktree Mode isolates a conversation into its own Git worktree (but only for eligible Git folders, so mixed projects still mutate shared state), and the managed API owns a hosted environment whose lifetime and retention are independent of any interaction record. [Projects and Local/New Worktree modes](https://www.antigravity.google/docs/projects)

Two mechanisms make this concrete. First, a layered control plane of permissions (action-over-target, Deny > Ask > Allow), executable hooks at PreTool/PostTool/PreInvocation/Stop, and surface-specific sandboxing — none a single platform-wide switch. [Permissions](https://www.antigravity.google/docs/permissions) · [Hooks](https://www.antigravity.google/docs/hooks). Second, browser verification closes a visual observation loop the agent can actually run the app, see it, and even repair code from a screenshot or recording — yet no public contract carries a clicked rendered element back to an authored file, line, component or revision. [IDE browser subagent](https://www.antigravity.google/docs/ide/browser). So the browser improves acceptance evidence without closing the source-return loop.

The open Python SDK is telling about where the boundary sits: it exposes `Agent -> Conversation -> Connection`, the hook/policy layer, and a `localharness` proto handshake over a localhost WebSocket, but every runnable wheel bundles a closed Go binary. [SDK repository @ 6db963cb](https://github.com/google-antigravity/antigravity-sdk-python/commit/6db963cbe4587a7934fd6c2e007976a1b97ed655) · [pyproject bundled localharness](https://github.com/google-antigravity/antigravity-sdk-python/blob/6db963cbe4587a7934fd6c2e007976a1b97ed655/pyproject.toml#L58-L67). That is a control-plane release, not an open implementation. The durable lesson: conversation identity, worktree revision, artifact revision and remote environment state are four different clocks, and "close the window" does not stop descendant tasks, schedules or sidecars. Design, in the end, is verified where the files landed — commit, merge or deliver it before treating the task as done. [Introducing Antigravity 2.0](https://www.antigravity.google/blog/introducing-google-antigravity-2)
