# Agent-Native Design

Agent-Native Design defines design as an application surface inside a general framework: its `templates/design/` tree is a complete, cloneable Design app with its own actions, data model, skills, editor bridge and documentation, and a user is expected to scaffold it, run it, deploy it and modify the application itself. Design here is not a feature call but a distributable program with its own job — [generate several interactive product or brand directions, refine the selected prototype visually or conversationally, and export owned source](https://www.agent-native.com/apps/design/).

The decisive mechanism is a single action contract that crosses every surface. In Agent-Native, [an action can be invoked from UI, agent, HTTP, MCP, A2A or CLI](https://www.agent-native.com/docs/template-design/), so creating a design, applying visual/source/token edits, capturing state, creating a branch, running quality fixes and exporting a coding handoff are the same operation whether triggered by a button or an agent. That shared contract is what keeps a human's click and an autonomous agent's tool from drifting apart.

The artifact itself is a self-contained Alpine/Tailwind HTML prototype backed by SQL design records. [The same files feed the live iframe preview and every export path](https://github.com/BuilderIO/agent-native/tree/16977942293d8f6953722e2f496847def4883f40) — there is no hidden conversion from a proprietary canvas into "approximately matching" code. Branches are explicit: actions create, duplicate, edit and delete designs and spawn variants so alternatives are compared before one direction continues, and visual tweaks, source edits, component ops, breakpoints, motion and shader changes all converge back on prototype state rather than producing untracked screenshots. Because a selected runtime element carries [source location and hit-test context via generated editor-bridge modules](https://github.com/BuilderIO/agent-native/tree/16977942293d8f6953722e2f496847def4883f40/templates/design), a visual edit action can target source directly. Authority rests with the standalone prototype and its SQL records — design, preview and delivery all read the same source.
