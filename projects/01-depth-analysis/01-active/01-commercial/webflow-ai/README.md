# Webflow AI

Webflow AI answers "what is design" by refusing to point at a single artifact and instead pointing at a **site** that several different authorities edit on their own clocks. The hosted Webflow site graph — pages, elements, classes, variables, components, CMS, locales, interactions, publication state — is the shared object every feature mutates, but the AI is not one generator with one result. It is an umbrella over five machinery types that share the site yet do not share one lifecycle: the AI site builder, the in-product Assistant, AI code components, the deprecating App Gen, and the remote Webflow MCP. There is no one "generate" button whose output is a design; there is a set of governed write-channels, each terminating in a different corner of the same hosted graph and each with its own promotion gate.

The decisive mechanism is that **every rewrite is scoped to a gate before it counts as a design**. Prompt to a [Flowkit](https://developers.webflow.com/flowkit/getting-started/intro)-backed native site is the flagship path: describe the business, approve up to five pages and their sections, then "Generate design" materializes variables, reusable component classes, `is-*`/`on-*`/`gap-*` combo classes, breakpoint modifiers and a Style guide as real Webflow objects — so the output stays editable as a normal site instead of becoming a screenshot. But a generated plan is not yet a Designer site: regenerating discards your edits, and on a free Starter plan unselected pages are permanently deleted. The Assistant's refinement is deliberately *constrained insertion*, not free-form regeneration — [section design](https://help.webflow.com/hc/en-us/articles/34205154436243-Modify-page-designs-with-the-Webflow-AI-Assistant) inserts candidate classes and can add/reuse classes but cannot update existing ones, and [copy generation](https://help.webflow.com/hc/en-us/articles/38323375464723-Generate-and-refine-copy-with-Webflow-AI) writes only after the user clicks **Done**. The model conditions on the design system; it is not granted arbitrary write authority over the global system.

The sharpest tension sits where code enters. [AI code components](https://help.webflow.com/hc/en-us/articles/51168990228499-Build-AI-code-components) are genuine code — a React editor, live preview, managed npm packages, props surfaced in the Properties panel — but each is a single-file "code island": it cannot travel through DevLink, cannot be cloned, is stripped from site code export, and secrets are unsupported. Webflow owns the envelope even while exposing the source. By contrast [App Gen](https://help.webflow.com/hc/en-us/articles/46332369065875-Build-full-stack-web-apps-with-Webflow-AI) deploys a separate file-based full-stack application to Webflow Cloud — the closest thing the product has to a general "build me an app" answer — and that path is now entering deprecation, which converts its portability questions from theoretical into immediate acceptance requirements.

The clearest demonstration of authority-sharing is [Webflow MCP 2.0](https://developers.webflow.com/mcp/reference/overview): external agents write the native graph itself — elements, styles, variables, components, CMS — through a governed remote OAuth endpoint, constrained by the author's existing role, recorded in Site Activity, and needing the live Designer only for a few visual/session operations (others return `ModeForbidden`). Native identity is exact (a composite `{ component, element }` id in the older MIT [`webflow/mcp-server`](https://github.com/webflow/mcp-server) slice at `c4fa339`), but it deliberately never returns to application files, repository revisions, or exported HTML — the hosted document is the target family, period. The current remote implementation, OAuth service and Bridge App are newer than any public commit, so the mechanism is established at the product-contract level.

The result is a **many-clocks topology** the user must track: autosave vs staging vs production, Draft vs queued vs live CMS records, draft Optimize variations vs launched experiments, page branches whose merge overwrites content while deleting comments, backups that restore authoring state without rewinding external integrations, and a ZIP export that is a one-way static fork. A successful AI action, an acceptance, a build, and a publish are four different receipts. Webflow AI's craft therefore consists largely of knowing which clock a given prompt advanced and which gate still stands between it and a live site — design is not what the model draws, but which governed write-channel the prompt reached.
