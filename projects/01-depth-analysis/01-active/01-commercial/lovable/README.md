# Lovable

Lovable answers "what is design" as part of product delivery and nothing less: the design act is turning a brief into complete, publishable application source, inseparable from behavior, data and release in one managed project. Its Preview is not a design document and its artifact is not a mockup — the working object is a Lovable Project holding generated application code, chat history and automatic versions, with at least five independently recoverable states that advance on separate clocks: project code, Git branch, published snapshot, and Cloud/Supabase data ([docs](https://docs.lovable.dev/features/agent-mode), [changelog](https://docs.lovable.dev/changelog)). A version revert rewinds code, not database rows; a Git commit does not publish; no transaction restores all five together.

The decisive mechanism is that planning and build are different authority states. Plan mode may inspect the project and propose, but does not change code; approval switches to Build, which implements one task at a time against project source, with the active plan in `.lovable/plan.md` and approved plans archived. The current Preview Toolbar ([preview-toolbar](https://docs.lovable.dev/features/preview-toolbar)) funnels visual refinement back into the main chat: element selections, inline text edits, drawn annotations and pinned comments become agent context that only becomes durable when Build generates and saves code — a request that joins an ordered queue rather than mutating source directly.

Grounding that touch-to-source mapping, the distributed MIT package `lovable-tagger@1.3.3` maps JSX development source coordinates to DOM nodes through a `Symbol.for("__jsxSource__")` and `window.sourceElementMap` of `WeakRef`s, while the older `1.1.13` carried an in-memory Vite `virtualOverrides` layer that could patch a module and emit HMR before any persistence ([registry](https://registry.npmjs.org/lovable-tagger/1.3.3)) — evidence that a live Preview override is not durable source until a version is produced. The hosted core is closed; the public [`lovablelabs/mcp`](https://github.com/lovablelabs/mcp/tree/0336e6db8026b0f02cb89d1451cc48ea3f469791) repo is client/setup only. Git integration creates a new private repository and syncs one active branch; publish deploys an explicit snapshot; Preview and the published site ordinarily share the same backend, so test data is not automatically isolated. Design, here, is whichever surface — plan, Build, code editor or Toolbar — successfully advances project source, and durability is judged by the version emitted, not by what looked right in the Preview.
