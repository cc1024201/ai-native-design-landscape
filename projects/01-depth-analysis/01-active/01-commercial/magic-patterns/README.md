# Magic Patterns

Magic Patterns defines design as *versioned React source that a person and an agent can both own.* Its working authority is a Design's selected `activeArtifactId` — the editable React/TypeScript file snapshot that preview, Select + Visual Edit, chat, MCP and REST all target. Design is code, and the pivot object is not a picture or a node but an artifact id backed by a timeline of code snapshots. [Introduction](https://www.magicpatterns.com/docs/documentation/get-started/introduction) · [Prompt, Select and version restore](https://www.magicpatterns.com/docs/documentation/editor/how-to-prompt)

The implementation is a federation of four artifact identities that must not be collapsed: **Design** (editable code truth, one active artifact, version timeline), **Canvas** (spatial multiplayer graph over Designs — organization, not code source), **Design System** (a separate compiler and release line with its own mutable draft and immutable published `{major,minor}` versions, plus guarded `baseArtifactId` writes that 409 on drift), and **Inspiration** (a comparison document with in-place variants, no version history). [Canvas](https://www.magicpatterns.com/docs/documentation/projects/getting-started) · [Design System overview](https://www.magicpatterns.com/docs/documentation/design-systems/overview). Slide decks reuse the Design/artifact tools; published sites, ZIPs, GitHub repos, Figma layers and PDFs are delivery forks, not interchangeable backups.

The decisive mutation loop keeps a real pre-write gate: `/Plan` asks multiple-choice questions and streams an editable Markdown plan that auto-saves; nothing is written until the user chooses Build. After generation, **publish** compiles the whole artifact and can return 422 — so "source saved" and "preview runs" are separate gates. [Plan Mode](https://www.magicpatterns.com/docs/documentation/editor/plan-mode). A code-first parallel path clones an artifact, replaces whole files, publishes, then inspect the compiled preview.

The handoff to real systems is explicitly lossy and intentional. Magic Patterns normalizes inbound sources (GitHub folder links, local archives, NPM/Storybook, `.fig` files) into its own representations, and the official integration skill tells the receiving agent the destination codebase wins — discard the Vite/Tailwind scaffolding, `canvas.manifest.js`/`useScreenInit.js` plumbing, `data-id` instrumentation and mock data. [Integration skill](https://www.magicpatterns.com/docs/documentation/exporting/integration-skill) · [agent-plugins @ 95423db](https://github.com/magicpatterns/agent-plugins/tree/95423dbebeed508436bcedad8df39334f05b7f28). MCP provides a real least-authority `readonly` endpoint; GitHub "sync" is a normalized two-way transfer that strips unsupported code. The hosted editor, compiler, model router and storage are closed, so the public surface is a contract map of how code is authored, compiled, versioned and released — design being, in the end, the artifact id you can restore and republish.
