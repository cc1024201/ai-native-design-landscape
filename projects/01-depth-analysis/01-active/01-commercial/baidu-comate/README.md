# Baidu Comate

Comate's answer to "what is design" is deliberately split across two visual entry planes that both terminate in one place: **the project working tree is the authority, never the design document or the browser DOM**. Figma/Lanhu content enters as generated context; a running page element can return toward real source; and whatever survives is a workspace file change. Its decisive mechanism is a *dual visual convergence* that is stronger than a screenshot-only coding prompt but still short of a one-roundtrip design/code graph. [Comate AI IDE product manual](https://cloud.baidu.com/doc/COMATE/s/xlnvqe047) · [Preview and element debugging](https://cloud.baidu.com/doc/COMATE/s/8mc4sla81)

On the design-to-code side, a normal Figma selection becomes an explicit context bundle — Figma URL, name, exported `html`/`json`/`md` text, thumbnail, assets, a `designTokenPath` and a conversion rule — staged in a temporary `F2C` directory and handed to Agent, plus a bundled `figma2code` system Skill that tells Agent to inspect the actual project's framework, routing and component conventions before writing implementation code. Code Connect adds a semantic join from Figma-export markers to `.comate/components` metadata, which improves reuse without ever binding a Figma node to a file or AST range. The packet is grounded but lossy: it carries no native Figma graph, revision, or target source location.

On the running-page side, the select-element picker emits runtime component type/name, a DOM path, `outerHTML`, a rectangle and an optional `data-comate-source-path` carrying `file:line:column:tag`. A real **source-advisory writer** is the standout: for supported style/text edits with a usable hint, Comate parses JS-family files with Babel, rewrites the matching JSX/HTML directly and asks Agent to validate; every other edit is delegated to Agent through an edit-ledger prompt that treats the coordinate as the strongest *search starting point*, not an exact location. That is a genuine non-Agent source walker for a narrow class of edits, but the annotation is optional, ancestor-derived, and stale under HMR. The acceptance artifact in both branches is the clean rebuilt runtime, not the overlay. [Preview docs](https://cloud.baidu.com/doc/COMATE/s/8mc4sla81) · [Spec](https://cloud.baidu.com/doc/COMATE/s/Qmkoux53d) · [Mission](https://cloud.baidu.com/doc/COMATE/s/Smowccwio)

The client is closed but the shipped 3.4.1 Windows distribution is inspectable, exposing nine independent persistence clocks — native Figma/Lanhu documents, conversion cache, `.comate` memory/rules, Spec/Mission state, the working tree, checkpoints, preview DOM and delivery — with no global rewind across them. What makes Comate distinctive is that it hybridizes design ingestion (Agent-authored workspace code) with direct source rewriting, and the boundary between those two live inside one compiled client.
