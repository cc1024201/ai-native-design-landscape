# Replit Design

Replit Design answers "what is design" by locating it as an *exploration surface* inside the same Project as the running software, not as a separate file that is later exported. **Design** and **Build** are adjacent entry points into one Replit Project ([design-vs-build guide](https://docs.replit.com/design/design-vs-build)). Crucially, a Design frame (static or interactive mockup) and an Artifact (publishable app backed by project files and services) are distinct states, and a deliberate materialization step separates them: converting or applying a Design frame is an Agent operation that creates or rewrites an Artifact ([Build guide](https://docs.replit.com/design/build-your-design)).

The decisive mechanism is three mutation routes that look similar in the UI but carry different semantics. A deterministic **Visual Editor** edit (text, color, spacing, layout, image) writes underlying source code directly with no Agent loop or AI credits — the rendered element can produce a source mutation, with the caveat that a looped/reused element updates all its instances. A **targeted Agent** change attaches the selected frame as a snapshot or sends "targeted metadata" for hidden complexity. And **Build/apply** is a checkpointed Agent transaction that creates a new Artifact or rewrites an existing one, bracketed by before/after checkpoints, while the Design frame remains on the Canvas as reference.

Authority is deliberately split across objects: the **Frame** is the visual branching unit (suggestions create sibling frames beside the original), the **Artifact** is the publishable unit, and the **Project** is the integration/lifecycle unit where files, services, and publishing converge — Artifacts in one Project share backend, database, and deployment, so none is independently publishable. The clearest bridge from Canvas into file state is the design system: a generated system yields `tokens.json` → CSS variables → components plus a `DESIGN.md` ([storage guide](https://docs.replit.com/design/design-md)), giving Agent-readable file-backed style state. Persistence has at least two clocks — Git/file history and Agent checkpoints capture project files, conversation context, and optional database state, while the full Canvas board's serialization is undisclosed, so Canvas recovery cannot be equated with Git recovery from the public contract.
