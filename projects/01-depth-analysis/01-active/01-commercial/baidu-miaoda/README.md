# Miaoda (秒哒)

**What is design.** Miaoda defines design as a *gated* act: a requirement is not design until it has been structured into a PRD and explicitly confirmed, and an edited application is not delivered until it has been explicitly published. The real question the system asks is not "which model writes the page" but "which state has crossed which gate." Design is thus the hosted project and its trajectory—requirement conversation, generated application version, editor state and optional managed backend—advancing through two irreversible gates: a machine-readable generation confirmation, then an explicit release.

**How it is implemented.** The mechanism is a two-gate lifecycle around a hosted project, made concrete by a pinned MIT-0 adapter rather than a visible generator. Generation is triggered not by prose but by a control token: the official Skill package resolves a `prdAgentAction` artifact whose `generateApp` action must be confirmed once via `userConfirmation`, and the client polls `/api/v1/conversation/trajectory` through hosted `appFocus` states (`NOT_GENERATE`, `UNDER_CREATING`, `DESIGNING`, `RELEASED`…). The most consequential guard is identity: supplying an `appId` without the current `conversationId` silently forks a new application, so `appId + latest conversationId` is the minimum continuation identity.

LUI and GUI edits converge on a hosted editing version through a materialization edge—GUI font/color changes are absent from the exported ZIP until the user previews or publishes, so editor autosave proves recovery of intent, not the code. Backend state is a separate clock that can be shared across applications, and environment isolation is conditional: single-environment shares a database with production, while multi-environment promotes schema/data asymmetrically but never deletes plugins deleted in dev.

AI quality inspection is requirements-bound, not acceptance—repair is not guaranteed and real-world paths need manual testing. Release is an explicit operation returning a `releaseId`, and delivery forks into hosted site, custom domain, mini-program, native package, app square or a source ZIP that is an ejection fork with no reverse sync. No single restore rewinds application code, backend schema, domain and store package together.
