# Websim

Websim answers the question "what is design" with a runnable object rather than a picture: a prompt or a made-up URL becomes an interactive page, app, game or tool that lives on the platform as a hosted, remixable web project. The design is not a mockup you then build from — it *is* the running thing, clickable in the browser, with its own identity, shareable link and downloadable HTML. The [imagined-URL origin](https://websim.com/blog) still shapes the product: each generated project is a first-class hosted artifact, and the public gallery plus remix model let one creation become the input to another while the original survives as a separate creation.

What makes Websim's implementation distinct is that the platform injects optional platform abilities into the generated apps — [language-model chat and multimodal understanding, image generation, text-to-speech, hosted backend endpoints and data behavior, even multiplayer](https://websim.com/blog/make-ai-apps). Design therefore cannot be separated from a working application that has behavior, data and maybe other users. Websim owns the hosted project runtime and the generation context; downloaded HTML is a portable snapshot, not evidence of a synchronized local-source workflow.

Persistence and ownership follow that hosted model. The [terms](https://websim.com/tos) frame generated simulated webpages as outputs of a continuing account-based platform, and [first-party blog posts from July 2026](https://websim.com/blog) document active product changes such as connecting through a ChatGPT account. The public surface does not expose the project schema or promise a formal Git-like branch model, so remix identity and hosted continuation are recorded without inventing version semantics. Community-created apps stay artifacts on the platform unless they establish a separate maintained product. Websim's authority is the hosted, runnable, remixable project — design, behavior and hosting are one managed artifact.
