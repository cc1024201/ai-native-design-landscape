# Claude Design

Claude Design defines design as a **hosted working canvas that a person and Claude correct together**, plus a governed constraint layer that conditions it. The product is deliberately broader than one design-file format: runnable prototypes, microsites, decks, one-pagers and product concepts all live in one workspace and leave through different native formats — standalone HTML or ZIP, PPTX or PDF, a Canva destination, or a Claude Code handoff. The internal schema that reconciles those result types is not published. [Evidence: Claude Design product page](https://claude.com/product/design)

The decisive mechanism is **correction split by intent bandwidth**. Rather than one prompt-to-canvas channel, the user gets four addressable corrections: chat for composition-level change, an inline comment pinned to a clicked element, direct manipulation (drag, resize, align, edit text), and a Claude-created adjustment slider that exposes a continuous visual parameter like spacing or color so the user can tune, then ask Claude to propagate it. Claude participates not just in generating the result but in *choosing* which control is useful for that result — an artifact-specific control surface, even though its backing mechanism is undisclosed. [Evidence: launch / current product page](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)

Above individual projects sits the organization design system: Claude extracts colors, typography, components and layout patterns from heterogeneous assets — codebases, design files, screenshots, decks, brand materials, PDFs — the owner validates them against generated examples, then publishes and can set the system as the default inherited by future work. That makes the design system a governed product object, not a prompt attachment. [Evidence: design-system setup](https://support.claude.com/en/articles/14604397-set-up-your-design-system-in-claude-design)

The hosted project is the working editing authority because corrections, comments, saved directions and all exports originate there; exports and handoffs are exits that become new artifacts. Previews execute in a separate-domain sandboxed iframe behind permission-checked signed tokens, and a live MCP edge advertises read/write design scopes at `api.anthropic.com/v1/design/mcp`. Version semantics are thin — a user-visible "save current direction" checkpoint, no published revision graph or audit log — so the tool's power rests on inference-then-governance rather than durable source return.
