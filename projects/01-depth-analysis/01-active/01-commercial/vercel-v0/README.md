# v0

v0's answer to "what is design" is pointedly not a visual artifact: design is the current application source in an isolated per-Chat [Sandbox](https://v0.app/docs/sandbox), and everything else is a convergence plane or a delivery projection. Its Real structure is three clocks rather than one "v0 file": the Chat's VM files are the editable working state, a connected [GitHub branch](https://v0.app/docs/github) becomes the durable source of truth, and a [Vercel deployment](https://v0.app/docs/deployments) is a separately built build. No public transaction rewinds all three together — a healthy Preview is not production, a Chat version is not a Git commit, and restoring one does not revert the other clocks.

Because the files are the artifact, direct manipulation and AI both mutate the same working tree. `npm run dev`-grade Preview, a code editor, the agent's browser/Bash/MCP tools and a terminal all read and write one filesystem per Chat, and v0 [consumes MCP](https://v0.app/docs/MCP) while also [exposing v0 as an OAuth MCP server](https://v0.app/docs/api/v2/guides/mcp-server). The agent is not a loose generative layer: it gets real processes, can be granted graded [terminal permissions](https://v0.app/docs/terminal-commands), and — once Git is connected — code-changing messages land as automatic commits on a per-Chat working branch, making every accepted change an ordinary auditable diff.

The most instructive mechanism is [Design Mode](https://v0.app/docs/design-mode), which defines what "visual design" means here: it is rendered-element-to-source regeneration, not a second design document. Selecting an element in the live Preview produces Tailwind-aware style changes that stay **pending** — the Preview can look right while the source is unchanged — until Apply serializes them into the Chat and regenerates an updated, diffable source version. No stable DOM-to-source identity packet is published, so the closed runtime's grounding is inferred only from the git diff after Apply. Annotations are a lower-commitment sibling, review context rather than a mutation.

Four histories coexist — browser [Chat versions](https://v0.app/docs/versions), legacy v1 API versions, v2 current-files/Message restore (a state migration, not identity transfer), and Git — which is why v0 is best understood as a workspace whose design authority is whichever object you promote: current files while working, Git after connection, a deployment id when shipping. Design [Systems 2.0](https://v0.app/docs/design-systems-2) fits the same model: an adapter skill plus `v0.json` compresses a team's design language into generation context, verified against a starter app and drift-controlled only by pinning refs.
