# Stitch

Stitch answers "what is design" with a hosted project graph rather than a single rendered page. The unit of design is not one generated screen but a positioned system: generated source **screens**, their **ScreenInstance** placements on an infinite canvas, reusable **DesignSystem** assets, and a portable **DESIGN.md** intent document — four identities the SDK insists callers never collapse ([generated types](https://github.com/google-labs-code/stitch-sdk/blob/575a9fb6319bd9d1ce8175e4a89e5958e024bbfd/packages/sdk/generated/src/types.generated.ts#L331-L450)). Design is what lives at project level and survives export, not any single screenshot.

How it implements that is one graph operated from many planes. A human infinite canvas, a streaming Design Agent that reasons across the project, an Agent Manager running parallel ideas, voice, a remote read/write MCP endpoint, an object-oriented TypeScript SDK over it, and open Agent Skills all converge on the same `Project → Screen → DesignSystem` resource vocabulary ([MCP tool reference](https://stitch.withgoogle.com/docs/mcp/reference/)). Design intent is made portable as `DESIGN.md`: YAML tokens plus Markdown rationale that Stitch can generate, import, edit, apply and export — but its philosophy is explicit that tokens are context and prose is guidance, not imperative rendering commands ([PHILOSOPHY.md](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/PHILOSOPHY.md#L19-L44)).

The consequence of this design is a set of deliberate forks rather than a single true artifact. A **ScreenInstance** is a spatial placement, distinct from the source **screen** resource ([distinction](https://stitch.withgoogle.com/docs/mcp/guide/)); applying a design system demands an instance ID plus a source-screen name or it addresses the wrong layer. A project keeps its device-type frame, so moving App to Web is translation, not resize ([device types](https://stitch.withgoogle.com/docs/learn/device-types/)). Variants are branch-like grouped screens with no public merge or rollback ([variants](https://stitch.withgoogle.com/docs/learn/variants/)). The advertised code-to-design "roundtrip" is really a lossy relay — a script-free static HTML snapshot imported, then code re-materialized by a separate React export that never binds back to original component identity ([roundtrip](https://stitch.withgoogle.com/docs/skills/roundtrip/)). Delivery to AI Studio, Figma, Netlify, Lovable or Bolt opens a new downstream authority with no reverse sync ([Stitch updates](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/)). Design, in Stitch, is a hosted graph that can be steered from anywhere but fragments once it leaves the hosted center — and that is the model's defining tension.
