# Auto-Slides (`Westlake-AGI-Lab/Auto-Slides`)

Auto-Slides defines "design" as a build to be verified, not a canvas to be drawn on. The design lives in two cooperating text artifacts — a presentation-plan JSON that holds narrative intent and the LaTeX source that holds the exact executable composition — and the whole pipeline exists to get from a research-paper PDF to a compiled, then revised, Beamer deck. The rendered PDF is explicitly a projection: reading or changing it does not change the plan or the `.tex`. That refusal to treat the visual output as the authority is the project's sharpest idea.

The decisive mechanism is that AI mutates the source, not pixels. `modules/tex_workflow.py` loads or writes the plan, generates `output.tex`, validates and compiles it, and feeds build errors back into a repair step. Verification and repair agents operate on extracted content, the plan, and the source files; when a defect is accepted for repair, the mutation returns to LaTeX or planning state. Revision is even more explicitly file-grounded: `modules/revision_tex_generator.py` requires `--original-plan`, `--previous-tex` and `--feedback` together, so a revision sees the intended narrative and the exact previous implementation rather than regenerating blind from the PDF.

Compilation is a deliberately narrow, deterministic gate — `TexValidator` proves the source meets the TeX environment's syntactic and operational requirements and nothing more. It cannot prove content coverage, figure-claim pairing, legibility, or narrative effectiveness; the separate verification and repair stages exist precisely because a clean build is only one acceptance layer. Persistence follows session directories (`raw`, `plan`, `tex`, `images`, `verification`, `repair`, `speech`), which keeps provenance inspectable but leaves choosing a canonical predecessor to whatever paths the operator passes next run. The result is a research system whose authority is squarely plan-plus-LaTeX, with the PDF and speech script as companions.
