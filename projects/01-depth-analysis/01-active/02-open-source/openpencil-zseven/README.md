# OpenPencil (`ZSeven-W/openpencil`)

OpenPencil is a document-native AI vector editor: design is the practice of building a serializable vector document, and every human, agent, render and version path converges on that file rather than on application source or a browser DOM. The canonical artifact is the JSON `.op` document (`jian_ops_schema::PenDocument`) — a single editable scene model, with themes, variables, and even routes, state and interaction fields carried inside it — and `op_editor_core::EditorState.doc` is that same document, not a second scene to be reconciled later.

The decisive mechanism is a typed command boundary. UI actions, in-process AI tools and MCP write tools all reduce to `EditorCommand` values applied on the host/UI boundary; the agent does not own a parallel canvas. A node becomes a scene node by copying its existing document ID into the `LayoutScene`, so selection and hit-test results return straight to the corresponding `.op` node — canvas-node ↔ design-document-node identity, without an injected runtime selector.

**Agents cross the command boundary.** The built-in design loop advertises a narrow 15-tool surface assembled from the same schemas MCP uses, and concurrent subagents generate a constrained batch-design program (sandboxed JS calling `I(parent, node)` insertion primitives) whose recorded program is replayed as commands over isolated `BufferDocSink`s — real concurrency at the LLM layer, but convergence by command replay, not CRDT-style simultaneous mutation.

**Four histories, four different failure modes.** Crash-safe current-file save with atomic replacement, a 100-entry undo/redo snapshot history, an owner-ordered `CollabTxn`/`Commit` collaboration log, and libgit2 repository history with node-level `.op` merge are not interchangeable — none can be cited as proof of another. Design and code meet through explicit, asymmetric conversions: Figma/HTML/snapshots become `.op` nodes with a durable `ConversionSpec` provenance ledger, and `.op` becomes generated React/HTML/Vue/SwiftUI/Compose targets. The import/export surfaces surround the document; none replaces the `.op` file as the live editor's source of truth. The project is MIT and pinned at v0.8.3.
