# Websim

> Research status: **Architecture-level** · Last reviewed: **2026-08-12**

Websim began with imagined URLs but now treats each generated page app game or tool as a hosted remixable web project.

## The project is a runnable social artifact

A prompt or imaginary URL creates an interactive webpage rather than a static mockup. A user can continue prompting edit or remix another creation run the result in the browser share its identity and download HTML. The public gallery and remix model let a project become input to another project while retaining the original as a separate creation.

The current platform also injects optional capabilities into generated apps:

- language-model chat and multimodal understanding;
- image generation and text-to-speech;
- hosted backend endpoints and data-oriented behavior;
- multiplayer or other platform abilities exposed to the generated project.

These abilities make design inseparable from a working application. Websim owns the hosted project runtime and the generation context; downloaded HTML is a portable snapshot rather than evidence of a synchronized local-source workflow.

## Persistence and lifecycle

Terms define generated simulated webpages as outputs of a continuing account-based platform. Current first-party blog posts in July 2026 document active product changes including connection through a ChatGPT account. Public pages do not expose the project schema or guarantee a formal branch model so this dossier records remix identities and hosted continuation without inventing Git-like version semantics.

## Product boundary

Websim is counted once. Individual community-created apps are artifacts on the platform unless they establish a separate maintained product and team. Generated “documentation” sites on `on.websim.com` are not treated as authoritative Websim documentation merely because the platform hosts them.
